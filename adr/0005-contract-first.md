# ADR-0005: des-docs як джерело істини

- Статус: accepted
- Дата: 2026-11-05

## Контекст

Frontend і backend мають працювати незалежно. Якщо кожна команда тримає свою версію API або схеми, контракт розходиться. Потрібне одне місце, де зміна узгоджується і версіонується.

## Рішення

- `des-docs` містить product spec, OpenAPI, SQL schema, seed, ER, приклади, тестові вектори й ADR.
- Зміна контракту починається в `des-docs`, а не в app-репозиторіях.
- Кожен контрактний реліз отримує тег `contract-vX.Y.Z`.
- App-репозиторії містять копії `openapi.yaml` і `database/schema.sql` з header `Synced from des-docs@contract-vX.Y.Z`.
- CI у `des-docs` перевіряє OpenAPI, генерацію типів, schema+seed на PostgreSQL, посилання і збирає HTML docs.
- CI в app-репозиторіях перевіряє, що копія контракту відповідає тегу.

## Наслідки

- Обидві команди мають один контракт.
- Зміни потребують PR і рев'ю Tech Lead + BA.
- Копії в app-репозиторіях не редагуються вручну.
- Для семестрового проєкту достатньо копій, без submodule або приватного npm-пакета.
